2. THE XIAOMI THERMAL ARCHITECTURE & AES DECRYPTION
--------------------------------------------------------------------------------
On MediaTek MT6833 everpal, Xiaomi's proprietary daemon `/vendor/bin/mi_thermald`
regulates CPU, GPU, backlight, and charging thermal mitigation.

All thermal configuration files in `/vendor/etc/` are encrypted using AES-128-CBC:
- Cipher Key: `thermalopenssl.h` (16 bytes)
- Cipher IV : `thermalopenssl.h` (16 bytes)

3. THE 3 CRITICAL HARDWARE TRAPS ON MT6833
--------------------------------------------------------------------------------

3.1. THE SCONFIG 14 YOUTUBE CLAMP TRAP
On Qualcomm platforms, `sconfig 14` is often benchmark mode. On MediaTek MT6833,
`sconfig 14` maps directly to `thermal-youtube.conf`, an aggressive power-saving
profile for streaming video that clamps:
- Cortex-A55 to 1,048,000 kHz (1.04 GHz)
- Cortex-A76 to 1,129,000 kHz (1.12 GHz)
This collapses Geekbench scores to 331 Single / 1,033 Multi.
RULE: Never use `sconfig 14` on MT6833. Full capability is at `sconfig 10`.

3.2. THE KERNEL IPI SPINLOOP TRAP (/proc/driver/thermal/set_sspm_big_limit_threshold)
In `drivers/misc/mediatek/thermal/mt6833/src/mtk_thermal_ipi.c`, writing to this node:
```c
while (thermal_to_mcupm(THERMAL_IPI_SET_BIG_FREQ_THRESHOLD, &thermal_data) != 0)
    udelay(500);
```
On Linux 4.14 MT6833 with production SSPM firmware, the MCUPM power coprocessor
does not return an acknowledgment for this userspace IPI. The calling process
gets trapped in an uninterruptible kernel D-state loop, permanently spinning at
83%–84% CPU across 2 cores until reboot!
RULE: Never write to `/proc/driver/thermal/set_sspm_big_limit_threshold`.

3.3. THE LCD BACKLIGHT COOLING TRAP (mtk-cl-backlight)
In `thermald-devices.conf`:
```text
name:mtk-cl-backlight
def_target:2047
select_higher:0
```
`2047` is 100% PWM brightness. Writing `0` to its state forces brightness to 0,
causing a complete black screen upon unlocking the phone.
RULE: Leave backlight cooling devices strictly under kernel driver control.

4. THE ROOT CAUSE OF AOSP THERMAL THROTTLING
--------------------------------------------------------------------------------
In stock MIUI/HyperOS, Xiaomi's proprietary daemon (`joyose`) dynamically switches
`sconfig` to mode 10 or 20 when games launch.
On AOSP / Project Infinity, `joyose` does not exist. The system remains permanently
stuck on profile `0` (`thermal-normal.conf`).

Looking at `thermal-normal.conf`:
- Cortex-A55 throttling trigger: 36°C (drops from 2.0 GHz to 1.5 GHz at 44°C)
- Cortex-A76 throttling trigger: 36°C (drops from 2.4 GHz to 1.4 GHz at 44°C)
- Mali-G57 GPU throttling trigger: 41°C

Because 36°C is reached within 15 seconds of any heavy load, AOSP users
experience continuous thermal downclocking.

Under `thermal-nolimits.conf` (`sconfig 10`):
- Throttling trigger is elevated from 36°C to 55°C.
- CPU and GPU sustain 100% peak hardware clocks throughout extended gaming
  and compute sessions with zero frame drops.

5. STEP-BY-STEP IMPLEMENTATION FOR ADDSTER'S REPOSITORIES
--------------------------------------------------------------------------------

Option A: ROM Build Integration (device_xiaomi_everpal & vendor_xiaomi_everpal)
Apply `patch.patch`:

1. Vendor Tree (`vendor/xiaomi/everpal`):
   Replace `/vendor/etc/thermal-normal.conf` with `/vendor/etc/thermal-nolimits.conf`.
   Even if the system boots in mode 0, it automatically loads the 55°C NoLimits
   unthrottled policy.

2. Device Tree (`device/xiaomi/everpal/configs/thermal/thermal_info_config.json`):
   Raise AIDL thermal HAL skin and battery thresholds:
   - `mtktsAP` (Skin): [NAN, NAN, NAN, 55, 75, 85, 95]
   - `mtktsbattery`:   [NAN, NAN, NAN, 52, 57, 60, 62]

3. Device Init (`device/xiaomi/everpal/init/init.mt6833.thermal.rc`):
   ```rc
   on property:sys.boot_completed=1
       chmod 0664 /sys/class/thermal/thermal_message/sconfig
       write /sys/class/thermal/thermal_message/sconfig 10
   ```

Option B: Systemless KernelSU / Magisk Module
Install `ThermalMgmt/package/ThermalMgmt.zip` (Author: TesterProd):
- Overlays `thermal-normal.conf` with `thermal-nolimits.conf`.
- Sets `sconfig 10` upon boot completion.
- Verifies CPU policy scaling limits.
- Zero touches to backlight, refresh rate, or SSPM nodes.
