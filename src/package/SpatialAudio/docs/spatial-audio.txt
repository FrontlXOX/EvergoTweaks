1. TL;DR EXECUTIVE SUMMARY (FOR GOKU & ROM PORTERS)
================================================================================
On Android 16 (Project Infinity / LineageOS 23.0), the Xiaomi POCO M4 Pro 5G /
Redmi Note 11S 5G (everpal) experienced severe spatial audio routing
instability, CPU spikes, and audioserver crashes when connecting or disconnecting
wired headsets (3.5mm jack) and when rotating the screen.

Collaborator Goku (himanshuksr0007) drafted a 4-commit sequence to resolve this:
- 3181d48e: everpal: audio: Fix spatial audio routing storm on wired headset
- 9b44c369: everpal: audio: Fix spatializer routing (Dolby DAP stream postprocess)
- de93de3af: everpal: tighten AVB, enable 64-bit DRM and legacy audio policy
- 68fb9b12: everpal: audio: disable ultrasound proximity, enable legacy spatializer param query

CRITICAL EXCLUSION:
- Commit fc70a36b (switch to uncompressed EROFS) MUST NOT be applied without
  prior kernel-side EROFS staging, per Goku's explicit warning.

This subsystem provides:
1. A standalone flashable KernelSU / Magisk module (`SpatialAudio.zip`) that
   overlays the corrected `audio_policy_configuration.xml` and `audio_effects.xml`,
   injects early boot `resetprop` values, and configures runtime SELinux rules.
2. A unified, cherry-pickable `patch.patch` for `device_xiaomi_everpal`.

2. ROOT CAUSE ANALYSIS: THE SPATIAL AUDIO ROUTING STORM & GUEST HAL BREAKAGE
================================================================================

2.1. The immersive_out MixPort Concurrency Cascade
--------------------------------------------------
In stock AOSP audio policy configurations, `mixPort name="immersive_out"` lacks
concurrency constraints (`maxOpenCount` and `maxActiveCount`).
When a 3.5mm wired headset is inserted or removed, the MediaTek MT6359 `accdet`
driver fires rapid hardware interrupt bursts (debounce chatter).

AudioFlinger attempted to open multiple concurrent spatializer output streams on
the MTK primary HAL, producing ~20 round-trip createAudioPatch / releaseAudioPatch
transactions in under 60 seconds. This led to severe ALSA ring buffer starvation,
downmixing pipeline configuration faults (`Downmix_Configure error cascade`), and
audible audio stuttering.

SOLUTION:
Add `maxOpenCount="1" maxActiveCount="1"` to `mixPort name="immersive_out"`,
serializing all spatializer track allocations into a single, predictable hardware
pipeline. Expand channelMasks to explicitly support `AUDIO_CHANNEL_OUT_5POINT1`
and `AUDIO_CHANNEL_OUT_7POINT1` alongside `AUDIO_CHANNEL_OUT_STEREO` for true
multichannel spatial decoding.

2.2. Dolby DAP / DVL Global Effect Attachment Conflict
------------------------------------------------------
When Dolby Audio Processing (DAP) and Dolby Volume Leveler (DVL) are declared as
generic global effects in `audio_effects.xml`, AudioFlinger attempts to bind them
globally across all active output threads—including the spatializer thread
(`AUDIO_OUTPUT_FLAG_SPATIALIZER`).

Android 16 AudioFlinger explicitly rejects global non-spatial effects attaching
to the spatializer thread. When this rejection occurs, `AudioPolicyManager` enters
a continuous re-evaluation loop, tearing down and rebuilding audio patches.

SOLUTION:
Declare Dolby DAP and DVL as named effects only in `<effects>`, and map them
strictly per-stream inside `<postprocess>`:
- `music`: dap, dlb_music_listener
- `ring`: dlb_ring_listener
- `alarm`: dlb_alarm_listener
- `notification`: dlb_notification_listener, dlb_system_listener
- `voice_call`: dlb_voice_call_listener

This keeps the `AUDIO_OUTPUT_FLAG_SPATIALIZER` pipeline completely clean of
conflicting post-processing effects.

2.3. Single Speaker Geometry (sia81xx) vs Erroneous Speaker Spatialization
-------------------------------------------------------------------------
`everpal` ships with a single mono-class speaker driven by a dedicated SmartPA
amplifier (Awinic AW87389 / sia81xx). It lacks stereo or multi-speaker spatial
acoustics. When `persist.vendor.audio.spatializer.speaker_enabled` was unset
(defaulting to true on AOSP), Android's `SpatializerHelper` registered the speaker
endpoint as an active spatial target.

Switching audio between media playback and notifications triggered unnecessary
spatializer initialization cycles on a speaker incapable of rendering binaural
head-related transfer function (HRTF) cues.

SOLUTION:
Set `persist.vendor.audio.spatializer.speaker_enabled=false`.

2.4. Missing Head-Tracker HAL & The 43-Second Spinloop
------------------------------------------------------
`everpal` possesses no dedicated hardware head-tracking sensor HAL. On AOSP 16,
`ro.audio.spatializer.headtracking_supported` defaults to `true`. Without a physical
head-tracker HAL, `SpatializerHelper` launched an aggressive retry loop attempting
to initialize head orientation sensors every time a headset was connected.

Furthermore, every screen orientation flip fired sensor rotation events that
re-triggered spatializer routing checks (`ro.audio.monitorRotation=true`).

SOLUTION:
Set `ro.audio.spatializer.headtracking_supported=false` and
`ro.audio.monitorRotation=false`.

2.5. Ultrasound Proximity Absence & MediaTek Audio HAL Crash Cascade
--------------------------------------------------------------------
`everpal` utilizes standard optical/infrared proximity sensor hardware, NOT
ultrasound proximity audio modems. With `ro.vendor.audio.us.proximity=true`,
the MediaTek audio HAL initialized ultrasound capture/playback threads
(`vendor.audio.chk.cal.us=2`), leading to dead PCM loops and audioserver aborts.

SOLUTION:
Set `ro.vendor.audio.us.proximity=false`.

2.6. DecibelSpatializer HAL vs Legacy Parameter Query Fallback
--------------------------------------------------------------
The MT6833 platform audio stack does not implement Android 13+ extended spatializer
parameter queries (specifically parameters 10 and 13 for head tracking modes).
AudioFlinger spatializer queries failed with status `BAD_VALUE`.

SOLUTION:
Set `ro.audio.spatializer.use_legacy_param_query=true`.

3. HARDWARE & COMPONENT BREAKDOWN (EVERPAL AUDIO PIPELINE)
================================================================================
- SoC Audio Front-End (AFE): MediaTek MT6833P Digital Audio Interface
- Power Management Audio Codec: MediaTek MT6359 (Headset DAC/ADC + Jack Detect)
- Loudspeaker Amplifier: Awinic AW87389 Smart K Audio PA (mono-class, I2C/I2S)
- Headset Jack Detection: MT6359 Accdet (Microphone bias & button switch detect)
- Microphone Array: Dual analog mics (primary bottom mic + secondary noise-cancel mic)
- Earpiece Receiver: Dedicated voice call receiver (differential output from MT6359)

4. FULL SYSTEM PROPERTY & KERNEL/HAL TUNABLE MATRIX
================================================================================

| Property Key                                    | Stock AOSP | Tuned Value | Rationale                                              |
|:------------------------------------------------|:----------:|:-----------:|:-------------------------------------------------------|
| `persist.vendor.audio.spatializer.speaker_enabled` | Unset (true) | `false`   | Disables spatializer on single mono speaker amp        |
| `ro.audio.spatializer.headtracking_supported`   | Unset (true) | `false`   | Eliminates 43s head-tracker sensor discovery retry loop |
| `ro.audio.spatializer.use_legacy_param_query`   | Unset      | `true`      | Bypasses missing MTK params 10/13 HAL implementation   |
| `ro.audio.monitorRotation`                      | `true`     | `false`     | Prevents spatializer routing churn on screen rotate    |
| `ro.vendor.audio.us.proximity`                  | `true`     | `false`     | Disables non-existent ultrasound proximity modem       |

5. FLASHABLE MODULE ARCHITECTURE (MAGISK / KERNELSU SYSTEMLESS OVERLAY)
================================================================================
The flashable module is structured for 100% systemless operation on KernelSU,
Magisk, and APatch:

SpatialAudio.zip
├── META-INF/com/google/android/
│   ├── update-binary            # Installer stub with automatic permissions & chcon
│   └── updater-script           # # MAGISK signature
├── module.prop                  # Module identity metadata (author=FrontlXOX)
├── system.prop                  # Systemless property overrides applied at boot
├── post-fs-data.sh              # Early boot property injection & SELinux contexting
├── sepolicy.rule                # Runtime SELinux allowances for audio HAL & configs
└── system/vendor/etc/
    ├── audio_policy_configuration.xml # Tuned mixPort constraints & channel masks
    └── audio_effects.xml              # Decoupled DAP/DVL postprocess bindings

6. STEP-BY-STEP ROM DEVICE TREE INTEGRATION & VERIFICATION GUIDE
================================================================================

To integrate these fixes directly into your ROM source build:

1. Apply `src/package/SpatialAudio/patch.patch` to `device/xiaomi/everpal`:
   ```bash
   cd device/xiaomi/everpal
   git apply /path/to/EverpalTweaks/src/package/SpatialAudio/patch.patch
   ```

2. Alternatively, cherry-pick the exact commits from Goku's repository:
   ```bash
   git remote add goku https://github.com/himanshuksr0007/device_xiaomi_everpal.git
   git fetch goku
   git cherry-pick 3181d48e68b345b48091c0b1590e13c2601510d9
   git cherry-pick 9b44c3693d63eab24b5eb558fda72501bb5806a0
   git cherry-pick de93de3af829f971c10132bd4278113dfc0fc561
   git cherry-pick 68fb9b12bec280eaf65e04f44f4d44b27c4bfdcd
   ```

3. Verification on Connected Device via ADB:
   ```bash
   # Verify properties:
   adb shell "getprop | grep -E 'spatializer|proximity|monitorRotation'"

   # Verify audioserver health:
   adb shell "ps -ef | grep audioserver"
   adb logcat -d -s AudioPolicyManager AudioFlinger | grep -iE 'spatial|error'
   ```
