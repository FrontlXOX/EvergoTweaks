1. SYSTEM ARCHITECTURE & DUAL-STACK DECOUPLING
--------------------------------------------------------------------------------
Due to the Linux 4.14 kernel version-locking ioctl command structures (BASE_UK_VERSION
handshake in mali_kbase_core_linux.c), direct replacement of libGLES_mali.so crashes
SurfaceFlinger during boot.

To circumvent this, EverpalTweaks implements a dual-stack decoupled architecture:
  - System UI / SurfaceFlinger: Retains stock r32p1 libGLES_mali.so for 100% GLES stability.
  - Vulkan 1.3 Stack: Standalone Valhall r49p1 Vulkan 1.3 ICD (libVK13_mali.so) with
    matching HAL stub (vulkan.mali.so) and donor runtime (libged.so).

3. LINKER HOOKS & COMPANION SYMBOLS
--------------------------------------------------------------------------------
  - GpuAuxBlitAHardwareBuffer: Patched companion library libgpd1.so (.dynstr and
    .gnu.hash) using Bionic GnuHash::LookupByName bit-exact hashing to satisfy
    DT_NEEDED dependency.
  - Frame Rate Watchdog: Deployed donor libged.so (101 KB) to provide
    ged_fr_swd_frame_destroy and ged_fr_swd_mark_frame.
  - Arm Generic Timer: Calibrated PLATFORM_AGT_FREQUENCY_KHZ=13000 (13 MHz) in
    mali_platform.config.
  - AFBC Manifests: Injected Gralloc XML descriptors into /vendor/etc/gralloc/
    (gpu.xml, dpu.xml, dpu_aeu.xml, vpu.xml, cam.xml).

4. MALI VALHALL v1 KERNEL SPECIFICATION (JOB MANAGER vs CSF)
--------------------------------------------------------------------------------
  - Mali-G57 uses the Job Manager (JM) interface (BASE_UK_VERSION_MAJOR 11 in
    include/uapi/gpu/arm/midgard/jm/mali_kbase_jm_ioctl.h).
  - CSF (Command Stream Frontend) is solely used on 5th Gen GPUs (G710/G615/G720).
  - On Linux 4.14, shaders, SPIR-V pipeline caches, descriptor sets, and draw call
    dispatch execute 100% in user-space; kernel driver operates as a lightweight
    MMU mapper and job slot submitter.

6. ROM SOURCE TREE vs ROOT MODULE PACKAGING DISTINCTION
--------------------------------------------------------------------------------
  - ROM Source Trees (device_xiaomi_everpal & vendor_xiaomi_everpal):
    * SEPolicy: Pure AOSP Treble compliance. Vulkan libraries are mapped to
      'same_process_hal_file' via file_contexts. SurfaceFlinger and app domains
      natively possess execution rights. ZERO broad 'allow ... vendor_file'
      rules should be added to tree sepolicy, ensuring 100% CTS neverallow passes.
    * Runtime Architecture: Single unified libged.so runtime deployed to
      proprietary/vendor/lib64/libged.so. Both GLES and Vulkan 1.3 operate cleanly
      under the single unified driver.

  - Standalone Flashable Module (KernelSU / Magisk):
    * SEPolicy: KernelSU's MagicMount operates via OverlayFS (dev="overlay"),
      which strips extended security attributes and labels mounted files as
      generic 'vendor_file' or 'unlabeled'. The bundled sepolicy.rule is injected
      at boot by magiskpolicy strictly as a runtime shim to prevent OverlayFS AVC denials.
